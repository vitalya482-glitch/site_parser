# Site Parser — Agents.md

## Цель проекта

Создать минимальное браузерное расширение (Chrome / Edge, Manifest V3), которое локально, от имени обычной пользовательской браузерной сессии, собирает фактические объявления с OLX и строит собственную локальную выдачу без рекламной сортировки и нерелевантных результатов OLX.

Главная задача первой версии: пользователь задаёт точные условия поиска (например, `3090` в названии и/или тексте объявления), расширение просматривает доступные страницы OLX, собирает реальные объявления, фильтрует их по нашим правилам, сохраняет локально и показывает в собственном dashboard.

## Основные принципы

- Максимально маленький и понятный проект.
- Без отдельного сервера, OpenCart, Docker и Python.
- Чистые HTML/CSS/JavaScript и Chrome Extension Manifest V3.
- Работа локально в Chrome и Edge.
- GitHub используется для исходного кода и истории разработки.
- Данные пользователя по умолчанию хранятся локально (`chrome.storage.local`).
- Не зависеть от сортировки OLX.
- Не считать рекламные/продвигаемые позиции более релевантными.
- Не обходить CAPTCHA или явные антибот-ограничения. Работать с контентом, доступным обычной пользовательской сессии, с разумными задержками.
- Архитектура должна позволять позднее добавить другие сайты объявлений, не переписывая dashboard и фильтры.

## MVP — версия 0.1

### 1. Расширение браузера

Минимальная структура:

```text
site_parser/
├── manifest.json
├── src/
│   ├── background.js
│   ├── content.js
│   ├── storage.js
│   ├── parser/
│   │   └── olx.js
│   └── dashboard/
│       ├── index.html
│       ├── dashboard.js
│       └── style.css
├── icons/
└── Agents.md
```

Не добавлять фреймворки без реальной необходимости.

### 2. Поисковые правила

Пользователь должен иметь возможность создать правило, например `RTX 3090`.

Минимальные параметры правила:

- название правила;
- обязательный текст в названии объявления;
- обязательный текст в описании объявления;
- логика `AND` / `OR` между названием и описанием;
- исключаемые слова/фразы;
- минимальная цена;
- максимальная цена;
- URL/поисковый URL OLX, с которого начинается сбор;
- максимальная глубина страниц для одного сканирования.

Пример:

```text
Правило: RTX 3090
Название содержит: 3090
Описание содержит: 3090
Логика: AND
Исключить: 3080, ремонт, коробка, куплю
Цена: 150000–500000 KZT
```

Фильтрация должна выполняться нашим кодом после получения объявления, а не полагаться исключительно на поиск OLX.

### 3. Сбор выдачи OLX

Первый этап сканирования:

1. Получить карточки с доступной страницы поисковой выдачи OLX.
2. Из каждой карточки извлечь как минимум:
   - ID объявления, если доступен;
   - название;
   - цену;
   - URL;
   - город/регион, если доступен;
   - дату/время, если доступны;
   - признак рекламной/продвигаемой карточки, если его можно надёжно определить.
3. Удалить дубли по ID, а при отсутствии ID — по нормализованному URL.
4. При необходимости открыть страницу объявления и получить полный текст описания.
5. Применить наши поисковые правила.
6. Сохранить результат локально.

Парсер OLX должен быть изолирован в `src/parser/olx.js`, чтобы изменения DOM OLX не затрагивали остальное приложение.

### 4. Глубокий поиск

Ключевая функция проекта — возможность найти старое релевантное объявление, которое OLX показывает далеко в выдаче.

Сканер должен уметь последовательно обрабатывать несколько страниц результатов с задержкой между переходами/запросами.

Первый глубокий запуск может собрать большой локальный индекс. Последующие запуски должны использовать сохранённые ID и не выполнять лишнюю повторную обработку известных объявлений.

Не ставить целью максимально быстрый массовый scraping. Приоритет — устойчивость и умеренная нагрузка.

### 5. Локальный индекс

Использовать `chrome.storage.local` для MVP.

Для объявления хранить примерно такую модель:

```js
{
  id: "...",
  source: "olx",
  title: "ASUS RTX 3090 24GB",
  description: "...",
  price: 285000,
  currency: "KZT",
  location: "Алматы",
  publishedAt: null,
  url: "https://...",
  promoted: false,
  firstSeenAt: "...",
  lastSeenAt: "...",
  matchedRules: ["rtx-3090"]
}
```

`firstSeenAt` используется для определения `NEW`.

### 6. Dashboard

Dashboard открывается как полноценная страница расширения, а не ограничивается маленьким popup.

На первом экране показать:

- список поисковых правил;
- кнопку `Сканировать`;
- состояние текущего сканирования;
- дату последнего сканирования;
- количество найденных объявлений;
- количество новых;
- количество отфильтрованных;
- таблицу результатов.

Минимальные колонки:

```text
NEW | Название | Цена | Город | Дата | Найдено впервые | Источник
```

Клик по объявлению открывает оригинальную страницу OLX в новой вкладке.

Добавить сортировку хотя бы по:

- цене;
- дате первого обнаружения;
- дате объявления, если её удаётся получить.

### 7. NEW и история

Объявление считается новым, если его ID/URL ранее отсутствовал в локальном индексе.

При повторном обнаружении:

- не создавать дубль;
- обновить `lastSeenAt`;
- при возможности отслеживать изменение цены.

В дальнейшем можно добавить историю цен, но для MVP это необязательно.

## Этапы разработки

### Этап 1 — Proof of Concept

- Создать Manifest V3 extension.
- Запускать content script на OLX.kz.
- На открытой пользователем странице поиска собрать карточки.
- Вывести результат в console/dashboard.
- Проверить реальные DOM-селекторы OLX.

Критерий готовности: открываем страницу OLX с поиском `3090`, расширение получает реальные названия, цены и ссылки.

### Этап 2 — Точный локальный фильтр

- Добавить фильтр по названию.
- Добавить получение текста объявления.
- Добавить фильтр по описанию.
- Реализовать AND/OR.
- Реализовать исключаемые слова.
- Реализовать диапазон цены.

Критерий готовности: запрос `3090` показывает только объявления, соответствующие нашим правилам, независимо от того, что OLX считает релевантным.

### Этап 3 — Локальная база

- Добавить `chrome.storage.local`.
- Дедупликация.
- `firstSeenAt` / `lastSeenAt`.
- Маркер `NEW`.

### Этап 4 — Глубокое сканирование

- Последовательный просмотр страниц.
- Настраиваемая глубина.
- Пауза между страницами.
- Возможность остановить сканирование.
- Продолжение без повторной обработки уже известных объявлений, где это возможно.

### Этап 5 — Dashboard

- Нормальная таблица результатов.
- Фильтры.
- Сортировка.
- Поисковые правила.
- Статистика сканирования.

## Не делать в первой версии

Чтобы не раздувать проект, в MVP не нужны:

- серверная база данных;
- регистрация пользователей;
- облачная синхронизация;
- OpenCart-интеграция;
- Telegram;
- GitHub Actions scraping;
- React/Vue/Angular;
- отдельный C++ backend;
- машинное обучение;
- автоматический обход CAPTCHA;
- десятки источников объявлений.

Сначала необходимо доказать, что локальный браузерный сбор OLX работает устойчиво и действительно находит объявления лучше стандартной выдачи.

## После MVP

Если MVP работает хорошо, возможны:

- несколько одновременно сохранённых поисков;
- автоматические периодические проверки;
- desktop/browser notifications о новых объявлениях;
- история изменения цены;
- избранное и скрытые объявления;
- экспорт CSV/JSON;
- импорт/экспорт правил;
- дополнительные источники объявлений;
- единый локальный индекс по нескольким площадкам;
- Telegram-уведомления через отдельный опциональный сервис.

## Требования к изменениям кода для агентов

Перед изменением кода агент должен:

1. Прочитать этот `Agents.md`.
2. Не усложнять архитектуру без необходимости.
3. Сохранять разделение `parser -> storage -> filtering -> dashboard`.
4. Не смешивать OLX DOM-селекторы с UI dashboard.
5. Не добавлять зависимости, если задача решается стандартными Web APIs.
6. Не удалять работающий функционал ради рефакторинга без причины.
7. После каждого изменения проверять загрузку расширения в Chrome/Edge Manifest V3 без ошибок.
8. Для изменений парсера учитывать, что DOM OLX может меняться: селекторы должны быть централизованы и иметь разумные fallback-варианты.
9. Не реализовывать обход CAPTCHA/антибот-защиты.
10. Делать небольшие, проверяемые коммиты.

## Первая задача агенту

Начать только с Proof of Concept.

Создать минимальное Manifest V3 расширение, которое:

1. Загружается через `Load unpacked` в Chrome/Edge.
2. Работает на страницах OLX.kz.
3. На странице поисковой выдачи находит карточки объявлений.
4. Извлекает название, цену и URL.
5. Показывает собранные данные в простой странице dashboard расширения.

Не реализовывать глубокое сканирование, описание объявления и автоматизацию до проверки этого первого шага на реальном OLX.kz.
